# 对话史检索：设计与实测

> 目标一句话：她能记住"我们聊过什么"，并且能**引用回原文**。
> 建立于 2026-11-08。所有数字都是本机实测，不是估计。

## 一、数据从哪来

`~/.dsh/sessions/<工作区>/<会话>/session.v4.jsonl.zstd`

**注意：不是 jsonl，是多帧拼接的 zstd。** 按 `28 b5 2f fd`（ZSTD magic）切帧、逐帧解压。
这个坑踩过一次：字节偏移做增量在压缩流里行不通，改为**按文件 size+mtime 判增量**。

## 二、过滤规则（全在 config.json，不在代码里）

配置：`~/.dsh/ayy-archive/config.json`

| 规则 | 内容 |
|---|---|
| 只取 | `user/message`、`assistant/message` 的 **text 块** |
| 丢弃 | `reasoning`（内部思考）、`tool-call`、工具返回、系统注入 |
| 丢弃前缀 | `<system-reminder>`、`Current runtime context.`、压缩摘要、`【我记得的事】` 等 |
| 子会话 | **纯 UUID 的会话是子智能体的任务书，整类排除** |
| 分片 | 500 字/片，不跨会话 |
| 长消息 | >5000 字只留摘要（首 75% + 尾 25%） |

### 实测规模（2026-08-17 → 11-08，3 个月）

```
56 个会话 · 60,287 条记录
  user 3,040 / assistant 7,221 / tool 12,310 / 其它 37,281
过滤后：5,575 条消息 · 116 万字（去重 1,158,739）
          ↓
1,635 片 / 111 万字
```

**从 654 万字（含工具输出）压到 116 万字——砍掉 82%。**

## 三、检索三层

```
① 结构化过滤   scope（her / her_all / group / all）+ 日期区间 + 会话
② 关键词        ≥3 字走 FTS5 trigram，≤2 字走 LIKE（trigram 对两字词无效）
③ 语义         bge-m3 向量余弦 —— **默认关闭**，原因见下
```

### 关键词的评分

```
score = idf(词) × 词长² × (1 + 密度)
idf  = ln((N+1)/(df+1)) + 0.5
密度 = 出现次数 × 词长 / 片段字数
```

- **idf**：稀有词权重高（"阿水" > "面试"）
- **密度**：同一命中，短片段更贴题
- **虚词剥离**：`我们/聊过/是什么/怎么/的/吗…` 不参与相关性计算，否则覆盖度被撑大

### 相关性门槛（负样本靠这条）

```
命中内容字符 / 查询内容字符 ≥ 0.5 才返回
```
否则宁可她听到"没找到"，也不给一堆不相关的。

## 四、评测集（回归用）

`tests/archive-eval.json`：25 正 + 5 负（负样本是"库里根本没有的事"）。
跑分：`node tools/archive-eval.mjs`

### 基线演进

| 版本 | 命中@1 | 命中@3 | 命中@5 | MRR | 负样本拒答 |
|---|---|---|---|---|---|
| 初版（单关键词） | 52% | 76% | 92% | 0.654 | **0%** |
| + IDF / 虚词 / 覆盖度 | 56% | 84% | 92% | 0.703 | **100%** |
| + 语义（500 字整片，默认关） | 48% | 72% | 92% | 0.629 | 100% |

**关键教训：负样本从 0% 到 100% 是靠"覆盖度门槛"，不是靠向量。**

## 五、为什么向量默认关闭（别再来一遍）

实现：`lib/vector.js`（bge-m3，1024 维），1648 片入库 58 秒，体积约 6 MB。

实测数据：

```
「岛屿信息那个前端岗」目标片段（11-05）  cos = 0.494
五道负样本的最高分                     0.500 ~ 0.548
```

**目标片段的相似度比负样本还低。** 加语义后：

- 命中@1 从 56% 掉到 44%
- 负样本拒答从 100% 掉到 20%
- 调成"只做小加分"，仍不回血（48%/72%）

**根因**：片段 500 字，相关的那一句话被稀释。500 字的整片向量区分不开"聊过"和"没聊过"。

所以：`config.json` 的 `检索.语义 = false`。代码留着，条件成熟再开。

**开启条件（写死在这里，别凭感觉）**：细粒度切片（120–150 字子片）做完、评测复跑，命中@5 ≥ 92% 且负样本 ≥ 90%。

## 六、为什么还不上 reranker

两种失败要分开看（这一条是关键的判断依据）：

| 现象 | 例子 | reranker 能救吗 |
|---|---|---|
| **召回到了，排序被压下去** | 「留济南」11-02 两段排第 8 | **有机会**——把对的提到前三 |
| **根本没召回到（或相似度低于负样本）** | 「岛屿信息」0.494 < 0.548 | **救不了**——精排只能从候选里挑 |

**顺序（已定）**：子片段 → 重跑评测 → 还不行才加 reranker。
先做 reranker 是给一堆同类内容排先后，白花钱。

本机现状：Ollama 0.40.14 **没有 `/api/rerank`**；自己跑 Qwen3-Reranker 0.6B 要装 torch+transformers（约 3.6 GB）。已记入她的心愿单。

## 七、已知偏差（别再当 bug 查）

1. **#7「留济南这事怎么定的」排第 8**
   11-02 那两段在库里、`meta=0`、`scope=private`，用「考公当第二条腿」排第 1。
   被压下去是因为**我们自己在聊这个例子**，施工对话里反复出现"留济南"，而且片段更短（密度更高）。
   → 属于**测试污染测试集**，不是收录问题。接受它。

2. **元对话识别的盲区**
   当前规则：强词（`ayy_`/`dsh-`/白名单/SQLite）出现 1 个 → meta；弱词（插件/索引/入库/检索/向量）≥2 种 → meta；"索引+命中/引用"→ meta；带 `源月为安:`/`白昼菌:` 前缀（转贴记录）→ meta。
   **盲区**：施工对话引用业务词（"留济南"）时不带技术词，识别不到。
   → 这条规则**要持续补**，不是一次性例外。

## 八、运维

| 项 | 位置 | 频率 |
|---|---|---|
| 增量入库 | `tools/archive-ingest.mjs --all` | 计划任务 `AYY-Archive-Ingest`，每小时 :05 |
| 备份 | `tools/backup-archive.ps1` | 计划任务 `AYY-Archive-Backup`，每天 03:10，留 7 份 |
| 备份内容 | sessions（真源）+ archive.db（先 WAL checkpoint）+ config | 约 60 MB，0.7 秒 |

**增量原理**：`files` 表记 size+mtime，没变的跳过（实测 0.2 秒跑完）。
文件变了的处理：**先删该会话旧片段再重建**，改过/删掉的话不会留幽灵。

**forget**：`ayy_arch(forget, by:"id"|"day"|"session", value:…)`
- 正文 + FTS 一起删
- **立墓碑**（`tombstones`），重新 ingest 不会加回来
- ⚠️ 只清库，**底层 `sessions/*.zstd` 还在**——那是原文存档，要清得单独处理
